The quiet return of RSS

Selin Arslan · 12 Nov 2026 · 6 min read

Feeds never died. They moved out of the products that ranked them and back into readers people chose for themselves.

A small, chronological list does not decide what comes next. You open it in the morning and it is where you left it.

Four feeds survived the year. The rest were deleted, and nothing was lost by it.

What came back was the habit of finishing things: a list that ends, and a morning that does not ask what to read next.

How teams ship agent tooling

Five write-ups, one pattern: the tool call is the interface. What the teams that ship do differently, and the three things they all refuse to build.

01
The tool call is the interface

Every team describes the same shape: the API is the product, and the screen shrinks to supervision, approval and payment.

02
Discovery beats documentation

Models find capabilities at runtime. A stable schema and a readable error beat a docs site nobody parses.

03
Small surfaces win

The teams that ship keep one surface per job and let the model compose the rest.

The line that stuck

“The tool call is the product. The screen is supervision.”

— one of the five write-ups

  1. 01
    Tap share, then Shelf.

    The sheet lists Shelf first. One tap and the link leaves the app you were reading in.

  2. 02
    Shelf reads the source.

    The post text with what it quotes, a video’s title and description, or the title and description a page publishes.

  3. 03
    It lands with a summary.

    The save is on the shelf before you switch apps, with the source attached and a summary to skim.

X, LinkedIn, YouTube, any page: only the first screen changes. The steps, and the shelf it lands on, are the same four times.

Filed by an agent

  1. 01
    You ask the agent you already use.

    Research this, read these five, tell me what holds. The reading happens in the AI app, not here.

  2. 02
    It calls Shelf once.

    MCP from the phone, MCP or the CLI from the web. One request with a title, a note and its sources.

  3. 03
    The note is a save.

    Same ref, same search, same list a person reads. The agent does not get a shelf of its own.

The five sources it read travel with the note, so shelf show n7q3e prints the same thing you are reading.

Built, then filed

  1. 01
    It builds the document.

    Headings, three findings, a chart and the sources it read. HTML, not a screenshot of a chat.

  2. 02
    It files the artifact.

    One ref, next to the links — the same address a share would have taken.

  3. 03
    You read it in place.

    One column on the phone, wide in a browser, painted in a sandbox with scripts off.

Same ref, same search, same archive. An artifact is a save, so it folds, filters and copies like the link next to it.

The library

A shelf, not another feed.

Every save lands in the same place with what the page said and a summary of it. Nothing is sorted by an algorithm.

One place for every save.
A link from the Android share sheet, the web app or a browser tab lands on the same shelf, with its source and the date it was saved.
It reads before you do.
Shelf fetches what the page publishes, keeps the text, and adds captions for video when they arrive. A short summary tells you whether the piece is worth the ten minutes.
Search that remembers.
Search titles, summaries and the saved text. Topics and an archive keep the shelf from turning into a pile.
One library, three clients.
The web app, the Android app and the iOS app read the same account. Save on the phone, read it on the laptop.
A shelf for what an agent writes.
An agent files a research note or a finished HTML document with the shelf CLI, and reads it back through the same search. The shelf holds the artifacts, not only the links.
